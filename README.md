# JoodCraft — جودكرافت

منصة توليد الشهادات والعقود الرسمية بالعربية بأسلوب متقدم وعالي الجودة.
تطبيق مكتبي/ويب مبني على Flutter، يعالج بيانات الإكسيل ويولّد PDF بالخطوط
العربية **محلياً على الجهاز**، ويستخدم Supabase للأمان وحفظ القوالب والأصول فقط.

---

## 1. المعمارية الهجينة

| الجانب | المسؤولية | أين |
| --- | --- | --- |
| **محلي (Local Processing Engine)** | قراءة `.xlsx`، توليد PDF بخطوط عربية (RTL)، المعاينة الفورية، الطباعة والتصدير الجماعي | الجهاز (Windows/Web/macOS/Linux) |
| **سحابي (Supabase)** | Auth، حفظ `layout_data` للقوالب، Storage للأصول (شعار/توقيع/ختم)، RLS + Triggers | Supabase |

> قاعدة صارمة: **بيانات المستفيدين لا تُرفع إلى الخادم**. السحابة للقوالب والأصول فقط.

## 2. الهيكل (Modular Feature-First)

```
lib/
├── app/          # جذر التطبيق + الموجّه (Router) — نقطة التجميع
├── core/         # الطبقة المشتركة: الثوابت، الثيم، الخدمات، الأخطاء، الأدوات، الأدوات المصغّرة
└── features/     # كل وحدة مغلقة على نفسها (data / domain / presentation)
    ├── auth/                # المصادقة والبروفايل (Supabase)
    ├── dashboard/           # اللوحة والهيكل العام (Shell)
    ├── certificate_builder/ # محرك الشهادات (Landscape)
    ├── contract_builder/    # محرك العقود (Portrait)
    ├── batch_processor/     # محرك الإكسيل والجملة
    ├── templates/           # إدارة القوالب
    └── assets_manager/      # التوقيعات والأختام والشعار
```

قواعد ملزمة: لا استيراد مباشر بين الميزات، والأخطاء تُحوَّل كلها إلى
`AppException` عربي عبر `ErrorMapper`، ولا تُعرض رسالة إنجليزية للمستخدم.

## 3. التشغيل

### أ) تأسيس قاعدة البيانات (مرة واحدة)
افتح **Supabase → SQL Editor** ثم نفّذ محتوى `supabase_setup.sql` بالكامل.
السكريبت Idempotent (آمن الإعادة) ويُنشئ:
`public.profiles`، `public.templates`، `public.user_assets`، سياسات RLS،
الـ Trigger الذي ينشئ سجل الملف الشخصي تلقائياً، ومخزن `user-assets` بسياساته.

### ب) مفاتيح الاتصال (تُقرأ تلقائياً — بلا أي علامة تشغيل)
```bash
cp env.example.json env.json   # مرة واحدة، ثم املأ القيم
flutter run -d windows         # لا حاجة لأي flag
flutter run -d chrome
```

ترتيب الأسبقية وقت التشغيل (`AppEnv.load`):

| # | المصدر | متى يُستخدم |
| --- | --- | --- |
| 1 | `--dart-define` وقت البناء | أمر صريح يتفوق دائماً |
| 2 | `env.json` على القرص | أثناء التطوير — أحدث نسخة دون إعادة بناء |
| 3 | `env.json` المحزوم داخل التطبيق | نسخ الإنتاج على كل المنصات |

بناء صريح بقيم مختلفة:
```bash
flutter run -d windows \
  --dart-define=SUPABASE_URL=https://xxxx.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=eyJhbGciOi...
```

> `env.json` **إلزامي قبل البناء** لأنه أصل (asset) في `pubspec.yaml`؛ إن غاب
> يذكرك Flutter برسالة `No file or variants found for asset: env.json`، ولهذا
> بقي `env.example.json` كقالب فارغ. الملف مُستثنى في `.gitignore` (لا ترفع
> المفاتيح إلى Git). إن لم يُعثر على أي مصدر صالح يعرض التطبيق **شاشة تهيئة**
> إرشادية بدل الانهيار.

### ج) الجودة

```bash
flutter analyze                 # تحليل ساكن (يجب أن يكون نظيفاً)
flutter test                    # ‎526‎ اختبار وحدة + واجهة + طرف-إلى-طرف (بلا شبكة)
```

**اختبارات التكامل الحيّة** (تتصل بمشروع Supabase الفعلي، وتُتخطّى تلقائياً
إن لم تُمرَّر المفاتيح):

```bash
# 1) مجموعة الاختبارات: اتصال + تحويل الأخطاء + منع الوصول المجهول
flutter test test/integration --dart-define-from-file=env.json

# 2) دورة حياة كاملة + عزل RLS (تحتاج حساب اختبار مُؤكَّد البريد)
flutter test test/integration --dart-define-from-file=env.json \
  --dart-define=TEST_USER_EMAIL=you@example.com \
  --dart-define=TEST_USER_PASSWORD='...'

# 3) اختبار طرف-إلى-طرف يشغّل التطبيق الحقيقي ويسجّل الدخول فعلياً
flutter test integration_test/auth_flow_test.dart -d windows \
  --dart-define-from-file=env.json
```

> الاختبارات الحيّة موسومة بـ `live`؛ لاستثنائها: `flutter test --exclude-tags live`.
> وهي **تطلب العلامة صراحة** (`--dart-define-from-file`) خلافاً للتطبيق الذي
> يقرأ `env.json` تلقائياً — حتى لا تلمس الشبكة أحد أثناء `flutter test` العادي.
> الاختبار (2) يكتب قالباً تجريبياً واحداً ثم يحذفه بنفسه في نهاية التشغيل.

### المظهر الفاتح والداكن

- **ثيمان من منشئ واحد** (`AppTheme.light` / `AppTheme.dark`) مبنيان على
  `ColorScheme` — فتتكيّف الأسطح والحدود والحقول والنصوص تلقائياً مع السطوع.
- **تبديل بنقرة واحدة**: أيقونة ☀️/🌙 في الشريط العلوي للوحة التحكم
  (`ThemeToggleButton`) — تنقل إلى عكس المظهر المعروض حالياً.
- **حفظ التفضيل**: `ThemeController` يخزّن `ThemeMode` في
  `SharedPreferences` (فاتح/داكن/حسب النظام) ويعود للوضع المختار عند
  إعادة فتح التطبيق (يُقرأ قبل `runApp` بلا وميض).
- **تباين الورقة**: خلفية ورقة التصميم تبقى بحدود مرسومة وظل واضحين فوق
  مساحة العمل الفاتحة، وخلفية داكنة ليلاً — فلا تتداخل ألوان التصميم مع
  خلفية البرنامج في كلا الوضعين (محرّسة باختبار تباين WCAG).

## 5. ملاحظات على مشروع Supabase الحالي

تم التحقق من المشروع الفعلي (`urtgtatmzxwfjjxmzvfv`):

- الاتصال يعمل، ومزوّد البريد مُفعّل، والتسجيل مفتوح.
- **تأكيد البريد مُفعّل** (`mailer_autoconfirm = false`): بعد إنشاء الحساب لا توجد
  جلسة حتى يُؤكَّد البريد — والتطبيق يعرض تنبيهاً إرشادياً في هذه الحالة
  (`SignUpOutcome.requiresEmailConfirmation`).
- **الجداول أُنشئت و RLS مفعّلة**: الطلبات المجهولة ترجع `42501 permission denied`
  (وهو السلوك المطلوب) بدل `PGRST205` الذي كان يظهر قبل تنفيذ السكربت.

| الإجراء | النتيجة |
| --- | --- |
| نقر على عنصر | تحديده وظهور شريط خصائصه |
| سحب | نقل العنصر مع خطوط إرشاد ذكية والتصاق مغناطيسي بحواف الورقة/مركزها وبحدود ومراكز العناصر الأخرى |
| 8 مقابس | تحجيم من الجهات والزوايا (بلا نزول تحت الحد الأدنى) |
| مقبض التدوير | تدوير حول مركز العنصر (يُطبَّع ‎-180..180‎) |
| نقر مزدوج على نص | تركيز حقل «محتوى النص» مباشرةً |
| نقر مزدوج على الفراغ | إضافة نص جديد عند موضع النقر |

| سحب على الفراغ | صندوق تحديد جماعي (Marquee) — يحدّد كل المتقاطع معه |

| `Ctrl+C` / `Ctrl+X` / `Ctrl+V` | نسخ / قص / لصق (بإزاحة صغيرة وتحديد النسخ) |
| `Ctrl+D` / `Ctrl+A` / `Ctrl+S` | تكرار / تحديد الكل / حفظ القالب |
| `Ctrl+Shift+D` | تبديل اتجاه النص المحدد (عربي ↔ لاتيني) مع تحديث مؤشر الحقل فوراً |
| `Ctrl+[` / `Ctrl+]` | خطوة للخلف / للأمام |
| `Ctrl+Shift+[` / `Ctrl+Shift+]` | إلى الخلف تماماً / إلى المقدمة تماماً |
| أسهم اللوحة (+Shift) | إزاحة كل المحدد بدقة 1 (أو 10) وحدة تصميم — واستمرار الضغط يُسجَّل كخطوة تراجع واحدة |
| `Delete` / `Backspace` / `Esc` | حذف المحدد / إلغاء التحديد |

**حماية حقول الإدخال**: كل الاختصارات تُهمَل تلقائياً إذا كان المؤشر داخل
`EditableText` (الحقول الرقمية، محتوى النص، المسارات…) — فلا تُسرق نُقرة
`Delete` أو نسخ/لصق الموجّهة للحقل، ولا "يقفز" العنصر أثناء الكتابة.
الاستثناء الوحيد هو `Ctrl+Shift+D` (تبديل الاتجاه) الذي يُعالَج **قبل** الحماية
حتى ينقلب اتجاه حقل النص ومؤشّره في الحال أثناء الكتابة بدل انتظار الخروج منه.

**ضمان التركيز**: أي نقر على اللوحة — عنصراً كان أو مساحة فارغة أو مقابض
التحجيم — يعيد التركيز إلى عقدة اللوحة فوراً، فتعمل الاختصارات مباشرة بعد
النقر حتى لو كان المؤشر كان في حقل نصي في شريط الخصائص قبل ذلك.

**التحديد الجماعي**: `TemplateEditorController` يحتفظ بمجموعة معرّفات (لا
معرّف واحد)، وكل عمليات المجموعة (حذف/نقل/تكرار/ترتيب/شفافية) تُطبَّق على كل
المحدد؛ ويظهر في شريط الخصائص **لوحة مجموعة** مخصّصة بدل أدوات العنصر الواحد.

### خطوط الإرشاد الذكية (Smart Guides)

محرّك `SmartGuides` في `canvas_geometry.dart` يحسب أثناء السحب أقرب محاذاة
داخل تسامح **6 وحدات تصميم** على كل محور على حدة (فيمكن أن يلتصق المحوران
معاً)، ثم يُعيد الصندوق المُعدّل + خطوط الإرشاد النشطة:

- **مركز اللوحة**: خط رأسي عند منتصف العرض وخط أفقي عند منتصف الارتفاع يمتد
  على كامل الورقة.
- **بين العناصر**: مطابقة حافتَي (يسار/يمين) أو مركز العنصر المسحوب مع نظيرها
  في باقي العناصر.

تُرسم الخطوط عبر `SmartGuidesPainter` (لون أزرق سماوي مميز) فوق اللوحة أثناء
`PanUpdate` فقط، وتُخفى فور الإفلات (`PanEnd`). ويوجد مفتاح سريع
**«خطوط الإرشاد الذكية»** في شريط المحرّر الأعلى لتفعيلها/تعطيلها.

### الأداء وتجمّد المحرّر الطويل

عند استخدام المحرّر فترة مطوّلة مع خلفية إطار عالية الدقة كانت الصور تُفكّ
وتُرسم من جديد في كل إطار، فتتضخّم الذاكرة ويتجمّد التفاعل. عولج ذلك على
ثلاث جبهات:

- **ذاكرة الصور المفكوكة** (`AssetImageCache`): `UserAsset.bytes` كان يفكّ
  ترميز Base64 في كل نداء، و`Image.memory` يبني صورة جديدة كل `build` فيتغيّر
  مفتاح `MemoryImage` وتُمحى نتيجة `imageCache`. الآن تُفكّ البايتات وتُبنى
  موفّرات `MemoryImage` **مرة واحدة لكل أصل**، فيُعاد استخدام الصورة المفكوكة
  عبر الإطارات. تُفرَّغ الذاكرة عند حذف أصل أو إغلاق المحرّر أو فتح قالب آخر.
- **عزل طبقات الرسم**: خلفية المستند ومحتوى كل عنصر ملفوفان بـ`RepaintBoundary`
  مستقل، فتبقى رَستَرة الخلفية الثابتة عالية الدقة مخزّنة ولا تُعاد عند تحريك
  عنصر مفرد، وتُرسم **خطوط الإرشاد الذكية** على طبقة أوفلاي معزولة (`RepaintBoundary`
  + `IgnorePointer`) لا تلمس رَستَرة العناصر.
- **سجل تراجع واحد لكل سحب**: `beginInteraction`/`endInteraction` يحفظان الحالة
  مرة واحدة عند بدء السحب، فلا تُكتب حالة جديدة مع كل `PanUpdate` (وحدات بكسل).

### نمط الحفظ

- القالب كيان مستقل مرتبط بـ `user_id`، و`layout_data` تُكتب من
  `TemplateDocument.toJson()` — أي **`schema_version` مضمون دائماً**، وبذلك
  لا يرفضه قيد `CHECK` في قاعدة البيانات.
- المصدر الوحيد لشكل الجدول هو `SupabaseTemplateRepository`؛ وباقي التطبيق
  يتعامل مع واجهة `TemplateRepository` في `core` — فلا تستورد الميزات بعضها.
- الزر «قوالبي» يفتح القوالب المحفوظة (فتح/حذف) بلا مغادرة المحرر، وبعد الفتح
  يمكن تعديل القالب نفسه وحفظه في مكانه (تحديث لا إنشاء).
- الزر **«تصدير PDF»** في شريط الإجراءات (بجانب «حفظ القالب») يولّد الملف
  ويشاركه/يحفظه فوراً من داخل المحرّر بلا مغادرة شاشة التصميم، بنفس مسار
  المعاينة (`PdfGeneratorService` + `Printing.sharePdf`) وباسم `exportFileName`.
  ولا يُوقفه أي أصل مفقود: يُحلّ كل عنصر من مرجعه الحيّ أو نسخته المضمّنة
  (Base64) أو البايتات المعروضة على اللوحة، ويُكمل بقية المستند بلا حجب.

### المطابقة البصرية مع الطباعة

`ElementView` يرسم العنصر بنفس الخط والمحاذاة والدوران والألوان المستخدمة في
محرّك الـ PDF، والنص يُعرض في المحرر **بصيغته المنطقية** (`{{اسم_المتدرب}}`)
لتسهيل التحرير، بينما المعاينة والطباعة تُحلّان الحقول إلى قيمها النهائية.
مقياس اللوحة يُحسب من أبعاد الورقة نفسها (A4 عند 96dpi) فيبقى ما تراه عينك
مطابقاً لما يخرج من الطابعة.

**ضمانات الاتساق (مع اختبارات تحرسها):**

- **الأصول والخلفيات**: `AssetPdfImageResolver` يحلّ `userAsset` من مكتبة
  الأصول (خلفية/إطار/ختم/شعار/توقيع) ويضمّنه كـ`pw.MemoryImage`، ويقرأ
  البايتات من `AssetImageCache` بلا فكّ Base64 متكرّر. ولا يُخزّن فشل الحلّ
  نهائياً، فأصل لم يُستعَد بعد عند أول معاينة يُرسم في المعاينة التالية.
- **الأصول المضمّنة (Base64)**: عند إدراج إطار/شعار من مكتبة أصولي أو ربطه
  بعنصر من شريط الخصائص تُضمَّن نسخة Base64 داخل العنصر (`ImageElement.data`)؛
  ويحفظ `_withId` النسخة عند التكرار، ويضمّن `loadDocument` النسخة تلقائياً من
  المكتبة لعناصر القوالب القديمة بلا `data`. ويقبل القالب أيضاً خريطة أصول
  مشتركة (`TemplateDocument.assets`: معرّف ← Base64)، ونموذج `ImageElement`
  يقرأ `data` كسلسلة Base64 أو ككائن (`{'base64': …}`) ويزيل بادئة data URI.
  المرجع الحيّ يبقى مقدَّماً ما دام الأصل موجوداً، فإن حُذف الأصل من المكتبة
  رسم المحرّر والـ PDF النسخة المضمّنة بدل صفحة بيضاء، واحتياطاً أخيراً يستعيد
  المحرّك البايتات التي رُسمت على اللوحة (`AssetImageCache`) حتى لو لم يعد
  المتحكم يعرف الأصل. **التصدير لا يتوقف أبداً بسبب أصل مفقود** — يُكمل بقية
  المستند بلا أي شريط خطأ يحجب العملية.
- **النص العربي (تشكيل + اتجاه)**: كل نص يُمرَّر عبر `ArabicTextEngine` الذي
  يوصِل الحروف إلى صور العرض المتصلة (Presentation Forms‑B) ويرتّبها بصرياً
  قبل الرسم، ثم يُرسل إلى `pw.Text` بـ`textDirection: ltr` حتى **لا** تُعيد
  مكتبة `pdf` ترتيبه مرة ثانية (ضبط `rtl` مع bidi المدمج يقلب النص المشكَّل
  ويشوّهه)؛ والنص البصري مسبقاً (صور عرض ملصوقة) يُترك كما هو بلا تشكيل مزدوج.
  الخط العربي نفسه يُحمَّل كـ`pw.Font.ttf` ويُضمَّن في الملف.
- **محاذاة «ضبط»**: `pw.TextAlign.justify` غير مُنفَّذة فعلياً في مكتبة `pdf`
  (كل سطر داخلي يُمرَّر بـ`justify: false`)، فتُنجَز المحاذاة يدوياً في
  `ArabicTextEngine` حتى عرض الصندوق، ثم يُحاذى يميناً للعربية — فلا تنحاز
  الأسطر ولا تختلّ. وتُتاح **طريقتان** يختارهما المستخدم من شريط الخصائص (حقل
  «طريقة الضبط» يظهر عند اختيار «ضبط» فقط):
  - **فراغات** (`JustifyMode.spaces`: الافتراضي) — توزيع الفراغ الإضافي بين
    الكلمات دورياً.
  - **كشيدة** (`JustifyMode.kashida`) — تطويل الحروف بإدراج `ARABIC TATWEEL`
    (U+0640) في مواضع الوصل الصحيحة فقط (تُستخرج من أنواع الوصل في Unicode:
    الحرف السابق يتّصل أماماً والحالي يتّصل خلفاً)، دون توسيع الفراغات بين
    الكلمات — أسلوب الطباعة العربية. تُقاس كل إضافة بإعادة تشكيل السطر وتتوقف
    الزيادة **قبل** تجاوز عرض الصندوق، وتُحفظ نقاط انكسار الأسطر نفسها لأن
    الضبط يُطبَّق بعد التقسيم. **ملاحظة**: المعاينة داخل المحرر تُظهر ضبط
    الفراغات (فلاتر لا تُنفّذ الكشيدة)، والكشيدة تظهر في ملف الـ PDF المُصدَّر.
- **تطابق أسطر النص بين اللوحة والـ PDF**: حلّ الاتجاه والمحاذاة الفيزيائية
  مصدره واحد (`TextFlow`) يستخدمه المحرر ومحرّك الطباعة معاً، فلا يُمكن أن
  يترحّل اتجاه أو محاذاة بينهما. ويقارن
  `test/unit/text_alignment_parity_test.dart` **الأسطر النهائية فعلياً** عند كل
  قيمة `ElementTextAlign` × `ElementDirection` × (عربي/لاتيني/مختلط): أسطر
  مُقسِّم فلاتر مع قياس الخط الحقيقي مقابل أسطر `ArabicTextEngine.wrap` بقياس
  `PdfFont.stringMetrics` نفسه، ثم يولّد ملف PDF فعلياً لكل تركيبة — فأي انحدار
  مستقبلي في التشكيل/الترتيب/الانكسار/الضبط يكسر الاختبار فوراً.
- **اتجاه الكتابة في المحرر**: حقل تحرير النص وحقل اللوحة يفرضان `rtl` للعناصر
  العربية و`ltr` للاتينية حسب `TextElement.direction`، فيتحرّك المؤشر ومفاتيح
  الأسهم منطقياً مع الكلمة (كان الحقل مثبّتاً على `rtl` دائماً).
- **الخطوط المخصصة**: الخط المرفوع يُقرأ من مخزنه، يُسجَّل بـ`pw.Font.ttf`،
  ويُضمَّن في الملف (يُختار عبر `CustomPdfFonts` قبل الخطوط المضمّنة)، وإن كان
  غير متاح على الجهاز يرجع للمضمّن بأناقة بلا مربعات فارغة. وتُرفض خطوط
  CFF/PostScript (‎.otf بلا `glyf`/`loca`) برسالة عربية، لأن محرّك الطباعة لا
  يرسم محيطاتها فتظهر الحروف مشوّهة — تُقبل TrueType (‎.ttf) فقط.
- **الإحداثيات**: تحويل واحد موحّد `TemplateDocument.boxToPdfRect` (تصميم ←
  نقاط) يستخدمه المحرّك، بنفس معامل 72/96 ونفس الإزاحة الصفرية للورقة
  الافتراضية — فتطابق نسبة العنصر من الورقة بين المحرر والـ PDF. كما أن مربّع
  الختم يُحسب بأصغر ضلعين في المحرر والـ PDF معاً (كانا يختلفان).

## 7. مكتبة القوالب (المرحلة 5)

مكتبة واحدة تجمع **ثلاثة مصادر** في شبكة موحّدة مع بحث وتصفية وترتيب:

| المصدر | الثبات | أوفلاين؟ |
| --- | --- | --- |
| **جاهز (Preset)** | `PresetCatalog` — حمولات JSON محزومة في الكود | ✅ دائماً |
| **محلي (Local)** | `LocalTemplateStore` (SharedPreferences/ملف) | ✅ يُستعاد |
| **سحابي (Cloud)** | `SupabaseTemplateRepository` | يحتاج اتصال |

- **الفهرس الجاهز** (`lib/core/templates/preset_catalog.dart`) يوفر مجموعة
  احترافية: شهادات شكر وتقدير وإتمام دورة وتفوق، عقد عمل، عقد خدمات، وإفادة
  خبرة — بحقول ديناميكية عربية ليعمل الربط التلقائي في محرّك Excel.
- **الإجراءات**: معاينة PDF، فتح في المحرّر (الجاهز يُفتح مسودةً ليُحفظ
  كقالب جديد)، استيراد محلياً، حفظ كقالب مخصص في السحابة، استخدام في التوليد
  الجماعي، وتعديل/تكرار/حذف بحسب المصدر.
- **التكامل**: المرجع المختار يُمرَّر عبر الموجّه إلى محرّر الشهادات/العقود
  (`TemplateDraft`) وإلى محرّك الإكسيل (`TemplateRecord`) مباشرةً.
- **الاختبارات**: فهرس القوالب، المخزن المحلي (استعادة أوفلاين)، المتحكم
  الموحّد، وشاشة المكتبة (استيراد/حذف/توجيه) — بلا شبكة.

## 8. مدير الأصول والتوقيعات (المرحلة 5ب)

رفع الشعار والختم والتوقيع والإطار مرة واحدة، وإدارة مكتبتها محلياً أوفلاين:

```
lib/core/assets/
├── user_asset.dart          # نموذج الأصل (Base64 + النوع + الاسم)
├── asset_store.dart         # تخزين محلي (SharedPreferences) + في الذاكرة
├── assets_controller.dart   # رفع/فحص/تسمية/حذف + استعادة أوفلاين
├── asset_type_ui.dart       # أيقونة وتلميح وملاءمة افتراضية لكل نوع
└── asset_upload.dart        # منتقي الملفات + الرفع (مشترك)
```

- **أوفلاين بالكامل**: الأصول تُحفظ كـ Base64 محلياً (مثل الخطوط المخصصة)
  وتُستعاد في `main()` قبل الواجهة، بلا أي شبكة.
- **الثبات والمرونة**: الأصل يحمل معرّفاً (`asset_*`) يُشار إليه من عنصر
  الصورة في القالب بمصدر `مكتبة أصولي` (`ImageSourceKind.userAsset`)، فلا
  ينتفخ سجل القالب ببيانات الصور. حذف أصل يستخدمه قالب يُفقد الصورة بأناقة
  (تحذير في الطباعة) بدل الفشل.
- **الربط بمحرّك الطباعة**: `AssetPdfImageResolver` يحلّ `userAsset` من
  المكتبة المحلية ويضمّنها في الـ PDF، و`ElementView` يرسمها في اللوحة — ما
  تراه هو ما يُطبع.
- **الشاشة**: مسار `/assets` (المدير الكامل: رفع، بحث، تصفية بالنوع، إعادة
  تسمية، تغيير النوع، حذف)، وأزرار رفع مباشرة داخل شريط خصائص الصورة.
- **الجسر إلى المحرّر**: نافذة «من مكتبة أصولي»
  (`editor/widgets/asset_library_picker.dart`) تتيح اختيار أصل مرفوع مباشرةً من:
  شريط إضافة العناصر، وشريط خصائص الصورة، وقسم «خلفية المستند»؛ وتُصفّى
  الأنواع (مع إبراز «إطار» و«شعار» في منتقي الخلفية).
- **الإدراج المباشر**: اختيار «إطار» يُدرج عنصر صورة بارتفاع وعرض الصفحة
  كاملةً في **خلف كل العناصر** (ملاءمة `fill`)؛ وغيره يُدرج في المقدمة
  بالحجم والملاءمة الافتراضية لنوعه. العنصر الناتج مصدره
  `ImageSourceKind.userAsset` و`path` هو `asset_id`، فيظهر على اللوحة وفي
  الـ PDF المطبوع بلا أي خطوة إضافية.

## 9. الإنهاء المكتبي والتحزيم (المرحلة 6)

### اختبار طرف-إلى-طرف أوفلاين

`test/e2e/offline_journey_e2e_test.dart` يشغّل الرحلة الكاملة **بلا أي شبكة**:

1. **رحلة الواجهة**: رفع شعار من مدير الأصول الحقيقي (منتقي ملفات مزيّف يعيد
   بايتات صورة PNG صالحة) ثم الانتقال إلى مكتبة القوالب وفتح قالب جاهز في
   محرّر الشهادات الحقيقي.
2. **رحلة التوليد**: رفع شعار وتوقيع، فتح قالب جاهز، ربط الأصلين كعناصر
   `مكتبة أصولي`، تحميل بيانات Excel (CSV) وربط الأعمدة تلقائياً، ثم التوليد
   الجماعي الفعلي والتحقق من:
   - عدد الصفحات = عدد المستفيدين، وعدد الوثائق المولّدة.
   - **غياب أي تحذير صورة مفقودة** — أي أن أصول المكتبة تُحلّ داخل المحرّك فعلاً.
   - سلامة بنية الـ PDF: ترويسة `%PDF`، ذيل `%%EOF`، ووجود تدفق `/Image`.

> ملاحظة هندسية مهمة: محرّك `pdf` **يفكّ ترميز الصور فعلياً**، لذلك أي بايتات
> PNG تالفة تفشل. أضفنا `test/support/sample_image.dart` يبني PNG صالحاً
> برمجياً (CRC32 + `ZLibCodec`) — لا ملفات ثنائية في المستودع.

### التجاوب المكتبي

`test/features/desktop_responsiveness_test.dart` يبني الشاشات الرئيسية (المكتبة،
مدير الأصول، محرّر الشهادات، التوليد الجماعي) عند ‎1440×900‎ و‎1180×780‎
و‎1024×680‎ ويثبت خلوّها من أي تجاوز تخطيط (‎RenderFlex overflow‎).

على مستوى نافذة Windows:

- العنوان: `JoodCraft — جودكرافت` (بصيغة أسماء محارف كونية UCN لتعمل مع أي ترميز مصدر).
- الحجم الافتراضي: ‎1440×900‎.
- **حدّ أدنى مفروض** عبر `WM_GETMINMAXINFO`: ‎1024×680‎ منطقياً (يُقاس بمعامل DPI)
  فلا يستطيع المستخدم تصغير النافذة إلى حجم يُحدث تجاوز تخطيط.
- سمات ملف التنفيذ (`Runner.rc`): اسم المنتج `JoodCraft` ووصفه؛ والإصدار يُشتق
  تلقائياً من `pubspec.yaml` (`FLUTTER_VERSION`).

### بناء حزمة Windows للتوزيع

```bash
# ‎1) تأكد أن env.json موجود (أصل إلزامي للبناء).
cp env.example.json env.json   # ثم املأ SUPABASE_URL و SUPABASE_ANON_KEY

# ‎2) بناء نسخة الإصدار (Release).
flutter build windows --release

# ‎3) الناتج قابل للنشر مباشرة من:
#    build/windows/x64/runner/Release/
#    يحتوي joodcraft.exe + data/ + مكتبات DLL — انسخ المجلد كاملاً.
```

- **الخطوط والقالب والصور** محزومة كلها داخل `data/flutter_assets` — التشغيل
  أوفلاين بالكامل بلا تنزيل أي خط أو أصل.
- **بيانات المستخدم** (الخطوط المخصصة، الأصول المرفوعة، القوالب المحلية) تُحفظ
  في `SharedPreferences` لملف المستخدم على Windows، وتبقى بين التشغيلات.
- لبناء `MSIX` أو مُثبِّت (Installer) استخدم حزمة `msix` أو Inno Setup
  ووجّهها إلى مجلد `Release` أعلاه.
- **الاختبارات الحيّة** للشبكة منفصلة تماماً عن حزمة الإصدار ووسمها `live`
  (انظر القسم 3ج) — ولن تلمس الشبكة أبداً في `flutter test` العادي.
