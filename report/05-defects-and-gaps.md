## 5.2 🔴🔴 محرّك الـ PDF انحدر نقطياً (Raster) — أخطر عيب في المشروع

### ما حدث

مسار التصدير الأساسي (`PdfGeneratorService.generateBatch`) استُبدل بالكامل:

```dart
// lib/core/services/pdf_generator_service.dart:337-344
// المسار النقطي عالي الدقة (Rasterized) لضمان المطابقة 100% مع المحرر (300 DPI).
final Uint8List bytes = await RasterizedPdfBuilder.build(
  document: document, rows: rows, metadata: metadata, compress: compress);
```

و`RasterizedPdfBuilder` يرسم كل صفحة كصورة PNG عبر `OffscreenWidgetRenderer`
(`RenderRepaintBoundary.toImage(pixelRatio: 3.5)`) ثم يضعها كاملةً في صفحة PDF:

```dart
// lib/core/pdf/rasterized_pdf_builder.dart:127-130
return pw.FullPage(ignoreMargins: true,
                   child: pw.Image(memoryImage, fit: pw.BoxFit.cover));
```

### النتائج المقاسة

| المقياس | القيمة |
|--------|--------|
| بنية الـ PDF | صفحة = **صورة XObject واحدة** (`/Subtype/Image`, `Filter/ASCII85Decode`) |
| خطوط مضمّنة | **صفر** |
| نص قابل للنسخ/البحث | **لا** |
| تدرّجات متجهية | **لا** (تُرسَّم داخل الصورة) |
| شفافية عبر `ExtGState` | **لا** |
| حجم ملف 1–3 صفحات | **52 – 156 ميغابايت** (من سجل الاختبار: `PDF saved (156.1 MB)`) |
| حجم ملف 7 صفحات | ‎~52 MB |
| زمن توليد 3 صفحات | ‎~7 ثوان |
| مخرجات `debugPrint` في الإنتاج | ‎~6 أسطر لكل صفحة إلى الـconsole |

### لماذا 156 ميغابايت؟

1. `pixelRatio` مثبَّت بين 2.0 و3.5 ⇒ صفحة A4 ≈ 2778×3929 بكسل (‎~11 مليون بكسل).
2. الترميز PNG ثم يُغلّف بـ`pw.MemoryImage` الذي يُخرجه بـ**`ASCII85Decode` بلا
   `FlateDecode`** — أي ضغط تقريباً معدوم (‎+33% حجم).
3. `compress: true` في `pw.Document` يضغط التدفقات النصية فقط، لا الصور.
4. كل صفحة تُخزَّن بايتاتها كاملة دون إعادة استخدام (ولو كانت الصور متطابقة).

**الأثر العملي:** توليد 500 شهادة لن ينتج ملفاً يمكن إرساله بالبريد أو تخزينه أو
طباعته — سيُنتج غيغابايتات. **هذا عيب يحجب الإطلاق.**

### ما أصبح ميتاً بسببه

| الملف | الأسطر | المصير |
|-------|-------:|--------|
| `lib/core/pdf/pdf_render_engine.dart` (`PdfRenderer`) | 1,558 | لا يُستدعى في مسار الإنتاج |
| `lib/core/pdf/arabic_text_engine.dart` (تشكيل + كشيدة + bidi) | 485 | لا يُستدعى في مسار الإنتاج |
| `lib/core/pdf/pdf_generation_isolate.dart` | 132 | import بلا استخدام فعلي |
| `lib/core/services/pdf_generator_service.dart:493,600` | 2 دالتان | مرئّيتان في `flutter analyze` كشيفرة ميتة |
| منطق «طريقة الضبط» (فراغات/كشيدة) في `ArabicTextEngine` | — | أصبح بلا أثر على المخرج |

### الاختيار الهندسي الصحيح

النقطي يضمن **تطابقاً بصرياً 100%** بين المحرّر والمخرَج — وهو هدف مشروع — لكنه يجب أن
يكون **خياراً** لا مساراً وحيداً وأن يضغط فعلياً. الوضع المطلوب:

1. **مسار متجه (Vector)** للنصوص والأشكال والتدرّجات — يستعيد ~48 اختباراً أخضر
   ويعطي نصاً قابلاً للبحث وخطوطاً مضمّنة وحجماً صغيراً.
2. **مسار نقطي (Raster)** كخيار «مطابقة تامة» — لكن مع:
   - `FlateDecode` على الصور (أو JPEG بجودة 85% للصور الفوتوغرافية)؛
   - إزالة `pixelRatio: 3.5` الثابت إلى `dpi/72` فعلي؛
   - إعادة استخدام XObject متطابق (dedup)؛
   - إزالة كل `debugPrint` أو ربطها بـ`kDebugMode`؛
   - سقف حجم قابل للتشغيل.
3. تفعيل خيار «فيكتور» في `PdfExportType` (الموجود لكنه معطّل بشارة «قريباً»).

## 5.3 🔴 ميزة «الدعوات» مكسورة ومعزولة

### ما هو موجود فعلاً (وجاهز منطقياً)

| المكوّن | الملف | الأسطر |
|---------|-------|-------:|
| 7 قوالب دعوات (رمضان/عيد/زفاف) | `lib/core/templates/invitation_gallery.dart` | 850 |
| 3 مجموعات | `lib/core/templates/invitation_group.dart` | 53 |
| 9 مقاسات (A6/A5/طباعة/Instagram/Facebook/WhatsApp) | `lib/core/templates/invitation_size.dart` | 169 |
| تعقيم الأسماء العربية → لاتينية | `lib/features/invitations/domain/invitation_name_file.dart` | 278 |
| خدمة التصدير (PNG/PDF/ZIP/CSV) | `lib/features/invitations/domain/invitation_export_service.dart` | 215 |
| كاتب المخرجات (io/stub) | `lib/features/invitations/data/invitation_output_writer*.dart` | 143 |
| متحكّم الحالة كامل | `lib/features/invitations/presentation/providers/invitations_controller.dart` | 359 |
| **الشاشة** | `lib/features/invitations/presentation/screens/invitations_screen.dart` | **749 — لا تُصرّف** |
| الاختبارات | `test/features/invitations_bulk_test.dart` | 472 — **لم تُنفَّذ** |

### ما هو مكسور

1. **الشاشة لا تُصرّف** (22 خطأً) — تفصيلها في `04-quality-and-tests.md` §4.1.
2. **الشاشة غير مسجّلة في الموجّه**: لا يوجد `AppRoutes.invitations`، ولا فرع في
   `StatefulShellRoute`، ولا عنصر في `dashboardDestinations`. بحث نصّي كامل في `lib/`
   عن `InvitationsScreen` يُرجع **استيرادها في ملفها فقط**.
3. **الاستيرادات معطوبة**: تستورد `../../domain/invitation_group.dart` و
   `invitation_size.dart` و`invitation_templates.dart` وكلها **محذوفة من القرص** (نُقلت
   إلى `core/templates/` في إعادة الهيكلة غير المكتملة).
4. **الشاشة كُتبت لواجهة `file_picker` قديمة** (‎8.x/9.x) بينما المثبَّت 13.1.0.
5. **مفاتيح الترجمة العشرة غير موجودة** في أي من ملفات ARB العشرة.
6. **زر «حفظ» في الشريط العلوي لا يُظهر هذه الشاشة**، ونافذة «مستند جديد» لا تصل إليها
   رغم أن قسم «الدعوات والمناسبات» ظاهر في `project_preset.dart` — بمعنى أن مقاسات
   الدعوات تُفتح في محرّر الشهادات العام بدل شاشة الدعوات.
7. الاختبارات نفسها تستورد الشاشة المعطوبة ⇒ لولا قطع الجلسة لسقط الملف كاملاً.

**الخلاصة:** العمل المنطقي (النطاق + التوليد) منجز بنسبة عالية وجيد؛ ما ينقص هو
**ربط الواجهة فقط**. لكن تركه كما هو **يعطّل التحليل الساكن وCI كله**.
